# 系统架构概览

## 项目定位

INK 短信网关是一个基于 **Spring Cloud + Vue 3** 的现代化微服务短信网关系统，为业务系统提供统一的 API 网关路由、JWT 认证与用户管理能力。

## 服务清单

| 服务 | 端口 | 技术 | 职责 |
|------|------|------|------|
| **Gateway Service** | 8001 | Spring Cloud Gateway (WebFlux) | 路由分发、JWT 认证、CORS、限流 |
| **User Service** | 8002 | Spring Boot Web + MyBatis | 用户注册/登录/管理、密码加密 |
| **Admin Service** | 8003 | Spring Boot Web + MyBatis | 通道管理、短信记录管理、用户管理 |
| **API Service** | 8004 | Spring Boot Web + Netty | 短信发送 REST API、CMPP Server(:7891)、上游 CMPP 连接池（数据库配置，可热刷新） |
| **channel 模块** | - | Netty CMPP 2.0 | CMPP 协议定义、编解码器、会话管理 |
| **core 模块** | - | Netty Client | 上游 CMPP 连接管理：心跳、重连、消息路由 |
| **Common Module** | - | JAR 依赖 | 工具类、常量、异常处理、统一响应 |
| **Frontend** | 3000 | Vue 3 + Vite + Element Plus | SPA 单页应用 |

## 请求链路

```
浏览器 → Frontend(:3000)
       → Vite Proxy (/api → :8001)
       → Gateway(:8001)  ── JWT过滤器验证 ──
       → User Service(:8002)  ── 业务处理 ──    (路由: /api/user/**)
       → Admin Service(:8003) ── 管理操作 ──    (路由: /api/admin/**)
       → API Service(:8004) ── 短信处理 ──      (路由: /api/sms/**)
       → MySQL / Redis / CMPP Server
       → 原路返回 Result<T> JSON
```

1. **前端发起请求**：Axios 实例 `baseURL: '/api'`，Vite 开发代理将 `/api` 转发到网关 `:8001`
2. **网关拦截**：`JwtAuthenticationFilter` 检查白名单，非白名单路径需携带 `Authorization: Bearer <token>`
3. **路由转发**：网关匹配 `Path=/api/user/**`，通过 `lb://user-service` 负载均衡到用户服务；匹配 `Path=/api/admin/**`，通过 `lb://admin-service` 负载均衡到管理服务；匹配 `Path=/api/sms/**`，通过 `lb://api-service` 负载均衡到 API 服务
4. **用户服务处理**：Controller → Service → Mapper → MySQL，Redis 缓存用户信息/Token
5. **统一响应**：所有接口返回 `Result<T>` 格式 JSON（code / message / data / timestamp）

## Maven 模块关系

```
ink-sms-gateway (根目录)
└── backend/
    ├── pom.xml             (根 POM, pom)
    ├── common              (JAR, 公共依赖)
    ├── channel             (JAR, 依赖 common + netty)
    ├── core                (JAR, 依赖 channel + common)
    ├── gateway             (JAR, 依赖 common)
    ├── user-service        (JAR, 依赖 common)
    ├── admin-service       (JAR, 依赖 common)
    └── api                 (JAR, 依赖 channel + core + common)
```

根 POM 通过 `<dependencyManagement>` 统一管理所有依赖版本，子模块不单独声明版本号。
