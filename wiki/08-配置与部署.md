# 配置与部署

## 环境要求

### 软件依赖

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 17+ | 编译运行后端 |
| Maven | 3.6+ | 构建后端 |
| Node.js | 18+ | 运行前端（不支持 v24，vue-tsc 兼容性问题） |
| MySQL | 8.0+ | 数据持久化 |
| Redis | 6.0+ | 缓存 |
| Nacos | 2.3+ | 服务注册与发现（standalone 模式） |

### 服务器最低配置

| 资源 | 最低配置 | 推荐配置 | 说明 |
|------|---------|---------|------|
| 内存 | 2GB | 4GB | 4 个 Spring Boot 服务各占 ~300-400MB RSS |
| CPU | 2核 | 4核 | CMPP 消息处理 + Spring Boot 启动需要算力 |
| 磁盘 | 20GB | 40GB | 应用包 ~220MB，主要消耗在日志 |
| 带宽 | 1Mbps | 3-5Mbps | 取决于短信吞吐量 |

> **2GB 内存注意事项**：需精细调优 JVM 参数（见下方 JVM 参数章节），建议配置 1-2GB Swap 作为 OOM 缓冲。4 个独立 Spring Boot 微服务在 2GB 内存下运行余量很小，流量波动可能触发 OOM Killer。

## 启动顺序

```
1. MySQL          ← 创建数据库和表
2. Redis          ← 启动缓存服务
3. Nacos          ← 启动注册中心
4. Gateway        ← 启动网关服务 (:8001)
5. User Service   ← 启动用户服务 (:8002)
6. Admin Service  ← 启动管理服务 (:8003)
7. API Service    ← 启动短信服务 (:8004，含 CMPP Server :7891)
8. Frontend       ← 启动前端开发服务器 (:3000)
```

### 本地开发环境启动

本地开发使用 `dev` Profile，通过 Maven 命令启动各服务：

```bash
# 各后端服务（分别在对应模块目录下执行）
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 前端
cd front && npm run dev
```

`dev` Profile 配置（`application-dev.yml`）：
- Nacos: `localhost:8848`
- Redis: `localhost:6379`（无密码）
- MySQL: 本地数据库连接
- 日志级别: DEBUG

### 生产环境启动

生产环境使用 `prod` Profile，通过 `deploy.sh` 脚本启动：

```bash
cd /opt/ink-sms/ink-sms-gateway-<timestamp>
bash bin/deploy.sh start
```

`prod` Profile 配置（`application-prod.yml`）：
- Nacos: `100.101.92.2:8848`（外部服务地址）
- Redis: `100.101.92.2:6379`
- MySQL: `100.101.92.2:3306`
- 日志级别: INFO

## 1. 数据库初始化

```bash
mysql -u root -p < backend/user-service/src/main/resources/db/init.sql
```

创建 `ink_sms_gateway` 数据库 + `users` 表 + 2 条测试数据。

## 2. 启动 Redis

```bash
# Windows
redis-server

# 默认配置
# host: localhost
# port: 6379
```

## 3. 启动 Nacos

```bash
cd <nacos-home>/bin
startup.cmd -m standalone
```

**Nacos 端口**：HTTP `8848`，gRPC `9848`（8848 + 1000）

> **重要**：Nacos 3.x 需添加 JVM 参数以兼容 Spring Cloud Alibaba 2023.x：
> ```bash
> set JAVA_OPT="%JAVA_OPT% -Dnacos.server.grpc.port.offset=1000"
> startup.cmd -m standalone
> ```

## 4. 启动后端服务

### 编译公共模块

```bash
cd backend
mvn clean install -pl common
```

> `common` 被 `gateway` 和 `user-service` 依赖，修改后必须先 `mvn install`。

### 启动网关服务

```bash
cd gateway
mvn spring-boot:run
```

端口：`8001`

### 启动用户服务

```bash
cd ../user-service
mvn spring-boot:run
```

端口：`8002`

### 启动管理服务

```bash
cd ../admin-service
mvn spring-boot:run
```

端口：`8003`

### 启动 API 服务

```bash
cd ../api
mvn spring-boot:run
```

端口：`8004`（HTTP）、`7891`（CMPP Server 监听下游 SP 连接）

> API 服务启动后会从数据库加载 CMPP 通道配置，自动创建连接池并连接上游 CMPP 服务器，进行 Connect 认证并开始心跳维持。

## 5. 启动前端

```bash
cd front
npm install
npm run dev
```

端口：`3000`，API 请求代理到 `http://localhost:8001`

## 配置详解

### 网关服务 — application.yml

**文件**：`gateway/src/main/resources/application.yml`

```yaml
server:
  port: 8001

spring:
  application:
    name: gateway-service

  cloud:
    nacos:
      discovery:
        server-addr: 100.101.92.2:8848      # Nacos 地址
        namespace: public
        group: DEFAULT_GROUP
      config:
        enabled: false                   # 不使用 Nacos 配置中心
        import-check:
          enabled: false

    gateway:
      discovery:
        locator:
          enabled: true                  # 开启服务发现自动路由
          lower-case-service-id: true
      routes:
        - id: user-service
          uri: lb://user-service         # 负载均衡到用户服务
          predicates:
            - Path=/api/user/**          # 路由匹配规则
        - id: admin-service
          uri: lb://admin-service        # 负载均衡到管理服务
          predicates:
            - Path=/api/admin/**         # 管理 API 路由
        - id: api-service
          uri: lb://api-service          # 负载均衡到 API 服务
          predicates:
            - Path=/api/sms/**           # 短信 API 路由

    data:
      redis:
        host: localhost
        port: 6379
        database: 1                      # 网关使用 DB 1
        timeout: 3000ms
        lettuce:
          pool:
            max-active: 8
            max-idle: 8
            min-idle: 0
            max-wait: -1ms

logging:
  level:
    com.ink.gateway: DEBUG
    org.springframework.cloud.gateway: DEBUG
    reactor.netty.http.server: DEBUG
```

### API 服务 — application.yml

**文件**：`api/src/main/resources/application.yml`

```yaml
server:
  port: 8004

spring:
  application:
    name: api-service
  cloud:
    nacos:
      discovery:
        server-addr: 100.101.92.2:8848
        namespace: public
        group: DEFAULT_GROUP
      config:
        enabled: false
        import-check:
          enabled: false

# CMPP 下游服务器配置（接受 SP 连接）
cmpp:
  server:
    port: 7891                           # 下游 CMPP 服务器端口
    allowed-sp-list: "test:123456"       # SP 认证列表（spId:secret 格式）
    boss-threads: 1
    worker-threads: 4

logging:
  charset:
    console: UTF-8
    file: UTF-8
  level:
    com.ink: DEBUG
    io.netty: DEBUG
```

> **CMPP 上游通道配置已迁移至数据库**：通道信息通过 `ink_channel` 表管理，由 `DbChannelConfigLoader` 在启动时加载，支持运行时通过 `POST /api/sms/channels/refresh` 热刷新。YAML 中不再配置上游通道信息。

## 生产部署

### 部署脚本

项目提供 `deploy.sh` 一键部署脚本，支持以下功能：

- 自动停止旧服务
- 启动 Nacos（standalone 模式）
- 依次启动 4 个后端服务（每个间隔 30 秒等待 Nacos 注册）
- 健康检查（检测端口是否监听正常）

服务定义：

| 服务 | 端口 | JAR 文件 | 配置文件 |
|------|------|----------|----------|
| Gateway | 8001 | gateway.jar | gateway-application.yml |
| User Service | 8002 | user-service.jar | user-service-application.yml |
| Admin Service | 8003 | admin-service.jar | admin-service-application.yml |
| API Service | 8004 | api.jar | api-application.yml |

### 构建脚本

Windows 环境使用 `build.bat` 一键构建：

```bash
.\build.bat
```

执行流程：Maven 后端打包 → Vue 前端构建 → 组装部署包 → 生成 tar.gz 压缩包。

输出位置：`deploy/ink-sms-gateway-<timestamp>.tar.gz`

### JVM 参数

生产环境通过 `deploy.sh` 中的 `JVM_OPTS` 统一配置：

**4GB 内存服务器（推荐）**：
```bash
JVM_OPTS="-server -Xms256m -Xmx512m -XX:+UseG1GC -XX:MaxMetaspaceSize=192m"
```

**2GB 内存服务器（极限优化）**：
```bash
JVM_OPTS="-server -Xms96m -Xmx192m -XX:+UseG1GC -XX:MaxMetaspaceSize=128m -XX:MaxRAM=384m"
```

> **内存分析**：每个 Spring Boot 服务实际 RSS 约 300-400MB（Heap + Metaspace + ThreadStacks + Netty直接内存 + JVM内部结构），4 个服务合计约 1.3-1.6GB。2GB 服务器需配合 1-2GB Swap 使用。

### Nginx 配置

生产环境通过 Nginx 反向代理前端静态资源和 API 请求：

```nginx
server {
    listen       80;
    server_name  sms-admin.moxan-studio.cn;
    root         /opt/ink-sms/web;
    index        index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass         http://127.0.0.1:8001;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_connect_timeout  30s;
        proxy_read_timeout     120s;
    }
}
```

## 已知事项与注意事项

### Nacos

- 必须以 **standalone 模式**启动（`startup.cmd -m standalone`）
- Nacos 3.x 与 Spring Cloud Alibaba 2023.x 存在 gRPC 端口偏移兼容问题，需设置 JVM 参数 `-Dnacos.server.grpc.port.offset=1000`
- Nacos 实际 HTTP 端口为 `8848`，gRPC 端口为 `9848`（8848 + 1000）
- Nacos `token.secret.key` 必须 ≥ 32 字节且 Base64 编码

### 网关

- 网关基于 **WebFlux**，不可引入 `spring-boot-starter-web` 或任何 Servlet 依赖
- Knife4j 配置在 WebFlux 环境下不生效
- JWT 密钥（`jwt.secret`）长度必须 ≥ 256 bit（32 字节），否则 HS512 签名报错

### 数据库

- `users` 表中 `username`、`email`、`phone` 有 UNIQUE 约束
- 索引 `idx_username`/`idx_email`/`idx_phone` 与 UNIQUE 约束产生的索引冗余
- `last_login_ip` 使用 `VARCHAR(45)` 兼容 IPv6 地址

### 公共模块

- `common` 模块修改后必须先 `mvn install`，否则其他模块引用的是旧 JAR
- Lombok 版本 1.18.40 支持 JDK 25

### CMPP / API 服务

- API 服务启动后会同时启动 CMPP Server（:7891）和从数据库加载通道配置连接上游 CMPP 服务器
- CMPP 上游连接支持自动心跳、断线重连和运行时热刷新（`POST /api/sms/channels/refresh`）
- CMPP Connect 认证 Timestamp 字段为 **10 字节 MMDDHHMMSS ASCII**（消息体 33 字节：SourceAddr(6) + AuthenticatorClient(16) + Version(1) + Timestamp(10)）
- Deliver 消息解析已适配 emay 虚拟短信网关格式（无 Msg_Src/Fee 字段，Src_Terminal_Id 为 21 字节固定格式）
- 压力测试表明 API 吞吐量可达 3,600+ msg/sec（20 并发）
- CMPP 通道配置完全由数据库 `ink_channel` 表驱动，支持运行时增删改和热刷新

### Spring Profile 环境隔离

- `application.yml`：公共配置（端口、路由、MyBatis 等）
- `application-dev.yml`：开发环境（本地 Nacos/Redis/MySQL、DEBUG 日志）
- `application-prod.yml`：生产环境（外部服务地址、INFO 日志）
- 本地启动：`mvn spring-boot:run -Dspring-boot.run.profiles=dev`
- 生产启动：`deploy.sh` 自动激活 `-Dspring.profiles.active=prod`

### 部署脚本

- `deploy.sh` 中 `APP_HOME` 基于脚本位置（`bin/`）向上一级定位包根目录
- 部署新版本时需先 `stop` 旧服务，解压新包后 `start`
- Nginx 的 web root 路径需通过 `sed` 更新为最新部署目录
